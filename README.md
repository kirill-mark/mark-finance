# Mark Finance — карманный финансовый директор

Личное веб-приложение по ТЗ «Карманный финансовый директор Кирилла» (v1.0, 23.09.2026). Отвечает на вопрос: **«Что я могу сделать с деньгами сейчас, чтобы выполнить будущие обязательства?»** Личные деньги и продакшн KINOMARK ведутся раздельно.

Приложение: **https://kirill-mark.github.io/mark-finance/** — вход тем же аккаунтом, что и в планировщике MARK. Можно поставить на телефон: «Поделиться → На экран Домой» (iPhone) или «Установить приложение» (Android).

## Что умеет

- **Сегодня:** до трёх действий «Нужно решить», доступная сумма (стресс-сценарий и базовый рядом, отметка полноты данных), на счетах / защищено / минимальный остаток, ближайшие 7 дней (просрочки выше), прогноз на 13 недель с переключением сценариев, «Из чего сложилось» у каждой итоговой суммы.
- **Календарь платежей:** по дням и неделям; фильтры по пространству, направлению, статусу, подтверждённости, проекту, контрагенту; полная и частичная оплата, перенос ожидаемой даты без скрытия просрочки, отмена с причиной, история.
- **Проекты:** заказные (продано / получено / ожидаемые затраты / оценка маржи) и собственные (бюджет / подтверждено / получено / не хватает / собственные вложения); смета с исходными суммами и прогнозом затрат; договорённости с подрядчиками, заменяющие оценку; показатели направлений (стоимость серии, съёмки на смену, затраты на принятую минуту); сравнение направлений.
- **Личные деньги:** бюджет по категориям, переменные траты распределяются по дням месяца, цели, подушка в месяцах, ожидаемые выплаты из продакшна с пометкой риска.
- **Партнёры:** гонорары, возмещения, займы, распределения прибыли; кто кому должен и за что; утверждённые пулы с методом наибольших остатков; «Оплатил за компанию личными».
- **Счета и операции:** остатки, журнал, переводы, сверка с корректировкой, исправление со сторно, пересчёт точки открытия.
- **Резервы и цели**, **симуляция решений** (трата, вложение, выплата себе) с вердиктом, причинами, максимумом на дату и более поздней датой.
- **Помощник:** текстом на русском — сводка, платежи, объяснение расчёта, проверка решений, черновики поступлений/расходов/договорённостей/переноса с карточкой подтверждения.
- **Импорт CSV** с проверкой повторов и **выгрузка** CSV/JSON; **журнал изменений**; **первая настройка** по шагам; **демо-режим** с вымышленными данными, который ничего не записывает.

## Установка (один раз)

1. **База.** Supabase (проект планировщика) → SQL Editor → вставить содержимое [`supabase/install.sql`](supabase/install.sql) → Run. Повторный запуск безопасен. Файл создаёт таблицы `cfo_*`, правила доступа, серверные функции и добавляет владельца. Почта владельца — в конце файла (`cfo_allowed_users`); если входишь другой почтой, поменяй её там.
2. **Сайт.** GitHub → Settings → Pages → Source: «Deploy from a branch», ветка `main`, папка **`/docs`**.

## Разработка

Нужен Node.js 24+.

```sh
npm install
npm test            # 57 тестов: расчёты T01–T33, база (PGlite), помощник, CSV, установка
npm run typecheck
npm run build       # сборка в docs/
npm run serve       # http://localhost:8790
node scripts/bundle-sql.mjs   # пересобрать supabase/install.sql после изменения миграций
```

Переменные сборки — в [`.env.example`](.env.example). Нагрузочная проверка: `npx tsx scripts/bench.ts`.

## Архитектура

```
src/
  shared/            деньги (bigint копеек), даты, модель данных
  modules/
    forecasting/     чистые функции: остатки, прогноз, лимит, симуляции, проекты, партнёры, личный бюджет
    recommendations/ сводка «Сегодня» и правила рекомендаций
    assistant/       распознавание намерений, сумм, дат и сущностей
    import-export/   универсальный CSV
    data/            разбор снимка базы в модель расчётного модуля
  app/               интерфейс (Preact), доступ к Supabase, действия записи
supabase/migrations/ схема, серверные функции, безопасность
tests/domain         финансовые инварианты и приёмочные сценарии
tests/integration    сохранение, доступ, идемпотентность на Postgres (PGlite)
docs/                собранное приложение для GitHub Pages
```

### Принятые решения (отличия от предложенного стека и уточнения ТЗ)

| Тема | Решение |
|---|---|
| Стек | Вместо Next.js + Prisma — **Supabase (Postgres) + статическое приложение на GitHub Pages**, как у планировщика: без отдельного сервера и хостинга. Миграции — SQL-файлы в `supabase/migrations`. |
| Где считается прогноз | Расчётный модуль — детерминированные TypeScript-функции без зависимости от интерфейса. Сервер отдаёт нормализованный снимок (`cfo_snapshot`), расчёт выполняется в браузере тем же модулем для экранов, симуляций и помощника. Все **записи и инварианты проверяет сервер** (серверные функции Postgres с блокировкой пространства, RLS, составные внешние ключи). |
| Доступ | Приложение закрыто: пользоваться могут только почты из `cfo_allowed_users` (настройка развёртывания). Каждая запись имеет `space_id`, доступ проверяется политиками RLS; чужие ID ничего не раскрывают. |
| Деньги | `bigint` копеек в базе и в расчётах; в API — строки целых копеек; float не используется. Проценты — базисные пункты, округление half-up, распределения — метод наибольших остатков. |
| Идемпотентность | Все денежные операции — серверные функции с ключом идемпотентности: повтор с тем же телом возвращает прежний результат, с другим — конфликт 409. Простые записи создаются с клиентским UUID; изменения — с проверкой версии. |
| Исправления | Проведённые операции не удаляются: сторно + новая версия в одной транзакции, погашения и резервы корректируются. Журнал изменений — неизменяемые триггеры. |
| Помощник | На этом этапе **без языковой модели**: правила распознают намерения из раздела 9.1, расчёты — тот же модуль. Запись — только кнопкой в карточке с точными суммами; устаревший черновик показывается заново. Модель можно подключить позже через серверную функцию Supabase, не меняя расчётов. |
| Регулярные платежи | Разворачиваются в события с ключом (правило, дата); при первом действии вхождение сохраняется отдельным планом. Неотмеченные прошедшие вхождения за 45 дней считаются неоплаченными сегодня и помечаются как требующие проверки. |
| Качество данных | «Недостаточно данных» (лимит `null`): нет счетов, не сверены остатки, налоги не настроены, не задан минимальный остаток, затраты без дат, неразобранный импорт. «Предварительно» (без положительного вердикта): устаревшая сверка, налоги внесены не на весь горизонт, нет даты окончания проекта, выплата из бизнеса под угрозой. |
| Изменение прогноза за неделю | Ежедневный итог прогноза сохраняется в `cfo_forecast_history`; обзор недели сравнивает с ним. |
| Демо | Демо-режим — только в памяти браузера, помечен и не записывает ничего; рабочие пространства создаются пустыми. |

### Ограничения и следующие шаги

- Голосовой ввод, банки, Telegram, push, приглашения партнёров, мультивалютность, распознавание документов — следующие версии (раздел 3.2).
- Языковая модель для помощника не подключена (решение первого этапа).
- Одновременные запросы T17 проверены логикой блокировки строки пространства; тестовая база однопоточная.
- Ежедневное фоновое обновление рекомендаций не настроено: они пересчитываются при открытии и после каждого изменения.
- Резервное копирование базы — средствами Supabase (ежедневные бэкапы на платных тарифах) и выгрузкой JSON из приложения.
